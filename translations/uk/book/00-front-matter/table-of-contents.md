# Зміст

## Частина I - Мислити як Principal Engineer

- Що таке Principal Engineer?
- Прийняття рішень в умовах обмежень
- Як ставити кращі інженерні питання
- Ownership поза кодом
- Інженерне судження й докази
- Залишати системи кращими, ніж ви їх знайшли

## Частина II - Закони

- Кожен стан має одного власника
- Кожен API є обіцянкою
- Кожна залежність є рішенням
- Час є залежністю
- Невикористана гнучкість є марнотратством
- Простота є функцією
- Докази перед упевненістю

## Частина III - Architecture Playbook

- Проведення меж, які переживають зміни
- Керування Change Radius
- Проєктування для відмови й відновлення
- Як добре використовувати ADRs і RFCs
- Перегляд архітектури до того, як вона затвердіє
- Заморожування архітектури без заморожування навчання

## Частина IV - Побудова продукту

- Від прототипу до продукту
- Проєктування для виробництва й польової реальності
- Конфігурація, варіанти й продуктові лінійки
- Observability в embedded systems
- Дисципліна релізів і шляхи оновлення
- Reference Project Walkthrough

## Частина V - Інженерна організація

- Технічне лідерство без формальної влади
- Design Reviews як спільна памʼять
- Побудова інженерних ритуалів
- Менторство через артефакти
- Узгодження команд навколо рішень
- Architecture Health Reviews

## Частина VI - Legacy

- Читання legacy system
- Пошук Silent Coupling
- Керування Utility Gravity
- Зменшення Boolean Explosion
- Безпечне видалення
- Рефакторинг без втрати довіри продукту
