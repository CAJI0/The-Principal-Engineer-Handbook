# Закони

Частина II формулює сім архітектурних законів, які повторюються в різних системах незалежно від мови програмування, платформи чи організаційної структури.

Ці розділи пояснюють, як Principal Engineer мислить про стан, API, залежності, час, гнучкість, простоту й докази. Кожен закон показує не абстрактне правило, а практичний спосіб зменшити майбутню вартість змін.

- Кожен стан має одного власника.
- Кожен API — це обіцянка.
- Кожна залежність — це рішення.
- Час — це залежність.
- Невикористана гнучкість — це марнування.
- Простота — це функція продукту.
- Докази перед впевненістю.
